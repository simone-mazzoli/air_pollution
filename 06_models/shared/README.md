# Shared Modeling Code

`shared/` contains code that should behave the same for the pretrained ResNet
experiments and the future CNN trained from scratch. Keeping these pieces shared
helps make the model comparison fair: both model families should see the same
stations, labels, patches, preprocessing, geographic buffer, and metrics.

Architecture-specific behavior belongs in `resnet/` or `cnn/`. Shared training
code should not need to know whether the high-resolution image encoder is a
frozen ResNet, a partially fine-tuned ResNet, or a scratch CNN.

## Files

### `config.py`

Stores shared experiment settings:

- selected model name;
- pollutant list;
- Sentinel-5P streams;
- batch size;
- DataLoader worker count;
- patch-cache setting;
- random seed;
- 100 km buffer distance;
- outlier caps for PM10 and PM2.5;
- CV epoch and patience defaults;
- TTA setting;
- result-path helper.

Model-specific learning rates and architecture sizes should stay in the model
folder config, such as `resnet/config.py`.

`NUM_WORKERS` controls PyTorch DataLoader multiprocessing. It currently defaults
to `0` for the university JupyterHub setup because the container has only 64 MB
of `/dev/shm`. With the large multimodal batches used here, multiple workers can
hit that shared-memory limit and fail with a bus error. This setting only
changes how batches are loaded; it does not change the model or experiment.

`CACHE_PATCHES` controls a lazy in-process RAM cache for loaded `.npy` patch
arrays. It defaults to `True` because `NUM_WORKERS=0` means patch reads happen
serially in the main process, and rereading the same station files every epoch
can be slow. The cache uses ordinary process memory, not multiprocessing shared
memory, and does not change the values passed to the model.

### `paths.py`

Defines repository-relative paths for processed labels, station folds, satellite
patches, and model results. The scripts use these paths so they can be run from
the repository root on a local machine or on JupyterHub as long as `data/` is in
the expected place.

### `folds.py`

Contains the geographic fold definitions and helper functions for reading
`station_fold.csv`. It also contains the German federal states currently assigned
to the sealed TEST region.

The fold file is generated by `06_models/00_assign_folds.py`. Later scripts read
the generated file instead of rebuilding fold membership during training.

### `data.py`

Loads labels and patches, prepares station-level annual labels, applies label
filters, checks patch availability, applies Sentinel-2 and Sentinel-5P
normalization, builds the PyTorch dataset, and applies the 100 km spatial buffer.
It also owns the lazy patch cache used by active training and prediction runs.

It also contains the rotation/flip training augmentation used by the current
experiments.

### `evaluation.py`

Contains metric helpers, prediction-table helpers, TTA evaluation, baseline
calculation, and denormalization back to concentration units.

The train-mean baseline here is the arithmetic mean concentration from the
training split. It is reported next to model metrics as a simple comparison.

### `training.py`

Contains model-independent training helpers:

- masked loss;
- parameter counts;
- optimizer parameter-group validation;
- DataLoader setup;
- BatchNorm-safe partial-batch handling;
- CV fold training;
- final epoch selection from CV `best_epoch` values;
- model metadata collection.

If a model needs special optimizer groups, the model can expose
`optimizer_parameter_groups(cfg)`. The shared helper only checks that the groups
cover exactly the trainable parameters.

### `models.py`

Selects the configured model package and returns its `build_model` function plus
its config dictionary. This keeps the runner scripts short while still letting
model-specific details live in the model folders.
